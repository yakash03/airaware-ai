## 2. Data Flow & Normalization Pipeline

### 2.1 Environmental Data Ingestion (`src/lib/providers/`)
1. **Request Coordinates**: User selects a location via `LocationSearch` (geocoded by Open-Meteo Geocoding API).
2. **Fetch Atmospheric Data**: Server requests:
   - `openMeteoAir.ts`: Hourly criteria pollutants ($\text{PM}_{2.5}, \text{PM}_{10}, \text{CO}, \text{NO}_2, \text{SO}_2, \text{O}_3$).
   - `openMeteoWeather.ts`: Hourly meteorological context (temperature, humidity, wind speed, wind direction, precipitation).
3. **Cache Validation**: Checked against in-memory TTL cache (`ttlCache.ts`):
   - Air Quality: 15 minutes TTL.
   - Weather: 15 minutes TTL.
   - Geocoding: 24 hours TTL.

### 2.2 Normalization & Units (`src/lib/normalize/`)
- Carbon Monoxide ($\text{CO}$): Converted from Open-Meteo raw $\mu g/m^3$ to CPCB standard $mg/m^3$ ($\div 1000$).
- All other pollutants preserved in verified standard units ($\mu g/m^3$).
- Timestamps tagged with data type: `MODEL_ESTIMATE` (current slot) and `FORECAST` (hourly projections).
- Freshness policy (`policy.ts`):
  - $< 60\text{ min}$: `FRESH`
  - $60\text{--}180\text{ min}$: `STALE`
  - $> 180\text{ min}$: `EXPIRED`

## 3. Deterministic Environmental Engines (No LLM Hallucinations)

In accordance with **Rule 4 ("Rules decide; the LLM explains")**, zero measurements, sub-indices, thresholds, or window rankings are generated by an AI model.

### 3.1 CPCB National AQI Calculator (`src/lib/aqi/indiaNaqi.ts`)
Implements the official linear interpolation formula from Central Pollution Control Board (MoEFCC, 2014):

$$I_p = \left[ \frac{I_{\text{HI}} - I_{\text{LO}}}{B_{\text{HI}} - B_{\text{LO}}} \right] \cdot (C_p - B_{\text{LO}}) + I_{\text{LO}}$$

- **Data Sufficiency Rule**: Requires at least 3 valid criteria pollutants, at least one of which must be $\text{PM}_{2.5}$ or $\text{PM}_{10}$. If fewer, reports `dataSufficient: false` without inventing values.
- **Maximum Operator**: Overall $\text{AQI} = \max(I_p)$.
- **Dominant Pollutant**: Pollutant yielding $\max(I_p)$.

### 3.2 24-Hour Best Window Engine (`src/lib/rules/bestWindowRules.ts`)
- Evaluates candidate multi-hour intervals across the 24-hour CAMS forecast.
- Computes average CPCB NAQI, minimum/maximum index bounds, and average particulate density.
- Ranks periods in ascending order of pollutant burden; Rank #1 is designated the **"Comparatively Most Favorable Window"**.
- Mathematically derives delta points and percentage savings relative to the diurnal peak window.

### 3.3 Indoor Air Environment Engine (`src/lib/rules/indoorAdvisorRules.ts`)
- Couples real outdoor NAQI with user-reported room characteristics.
- Generates targeted recommendations for ventilation, cooking aerosol isolation, traffic rush-hour buffering, damp wiping over dry sweeping, and purifier operation.
- Enforces strict non-sensor disclaimers: never fabricates indoor measurements.

## 4. Grounded AI & Reliability Architecture

```
                  ┌────────────────────────┐
                  │ Deterministic Backend  │
                  │ Output (Verified Facts)│
                  └───────────┬────────────┘
                              │
                              ▼
                  ┌────────────────────────┐
                  │  Gemini 2.0 Flash API  │
                  │  (System-Prompt Bound) │
                  └───────────┬────────────┘
                              │ Generated Text
                              ▼
                  ┌────────────────────────┐
                  │ Output Validator       │
                  │ (src/lib/ai/validator) │
                  └───────────┬────────────┘
                             ╱ ╲
              Passed Valid? ╱   ╲ Failed or Rate-Limited?
                           ▼     ▼
             ┌───────────────┐ ┌────────────────────────┐
             │ Client Render │ │ Deterministic Fallback │
             │  (Grounded)   │ │ Engine (Zero Downtime) │
             └───────────────┘ └────────────────────────┘
```

### 4.1 Strict Output Validation (`src/lib/ai/validator.ts`)
Before any AI output is returned to the client:
1. **Number Extraction**: Extracts all numerical tokens from the generated text.
2. **Grounding Verification**: Ensures every number exists in the verified input dataset (ignoring standard physical constants like 2.5, 10, or regulatory years 2014, 2021).
3. **Medical Assertion Filter**: Blocks forbidden clinical terms: `diagnosis`, `prescription`, `cure`, `completely safe`, `guaranteed safe`.
4. **Instant Fallback**: If validation fails or the API times out, the system automatically returns verified deterministic text from `deterministicExplanations.ts`.

## 5. Security & Privacy Architecture

1. **Client-Side Profile Storage**: Family member profiles and indoor questionnaire preferences are stored strictly in client-side `localStorage`. No user credentials, accounts, or tracking cookies are required.
2. **Zero Sensitive Health History**: The questionnaire asks only practical living space questions (windows, cooking, dust, road proximity); no medical diagnoses or personal health histories are collected.
3. **Server-Side API Key Protection**: `GEMINI_API_KEY` is loaded exclusively in server-side route handlers (`process.env.GEMINI_API_KEY`). It is never bundled into client JavaScript bundles or exposed in network payloads.
4. **Input Sanitization**: Geocoding search queries, coordinates, and chat questions are typed and validated with bounds-checking before downstream processing.
